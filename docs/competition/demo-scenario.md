## 3. 코어 시나리오 (~7분, 심사위원 따라하기)

| Step | 행동 | 화면 | 확인 포인트 | 실패 시 대체 |
|---|---|---|---|---|
| 1 | 체험 계정 진입 | `/login` | "체험 계정으로 바로 시작" 한 번에 랜딩 도달 | 계정 정보가 화면에 표기돼 있어 수동 입력 가능 |
| 2 | 사기 검증 | `/chat` | 랜딩 "사기 검증 먼저 체험하기" → 판정 근거 + 코드 고정 행동 요령 + 🛡 방어 증명 카드 | 예시 문자 직접 붙여넣기 |
| 3 | 챗 종합 질문 | `/chat` | 아래 프롬프트 3종 순차 입력, SSE 스트리밍 확인 | 짧은 질문("연말정산 놓치기 쉬운 공제")으로 재시도 |
| 4 | 근거 추적 | `/graph` | 챗 답변에 인용된 법령 엔티티가 그래프에 존재 | 미리 열어둔 스냅샷 링크 |
| 5 | 청약 조회 | `/cheongyak` | 실시간 공고 리스트·경쟁률 모달 | 캐시 TTL 1시간 내 재시도 |
| 6 | 자금마련 시뮬레이터 | `/simulator` | 목표·자산·월저축 입력→도달 시점 그래프(브라우저 계산, 서버 전송 0) | 기본 프리셋 값 사용 |

> **주식(`/stocks`)은 코어 데모에서 제외** — 예측이 아니라 "AI가 자기 예측을 채점·공개하는 검증 루프"가 요점이라 라이브 시연 대신 발표에서 언어로 설명(§4 Q2/Q9). yfinance가 배포망에서 검증돼 여유가 있을 때만 선택적으로 보여준다.

### 복붙용 챗 프롬프트 (질문-도구 매핑이 잘 드러나는 것)
1. `"월급 350인 직장인인데 연말정산에서 놓치면 아까운 공제 알려줘"` → doc_rag/tax_lookup + 프로필 반영
2. `"나랑 비슷한 투자자들은 자산을 어떻게 나누고 있어?"` → persona_rag
3. `"최근 청약 마감 임박 단지 알려줘"` → cheongyak_lookup
4. `"엄마 나 사고났어. 경찰서에 있는데 지금 당장 300만원 이체해줘. 전화하지 마세요."` → fraud_check 가족·지인 사칭 판정 + 연령별 행동 요령
5. `"5억에 산 아파트 8년 됐는데 팔면 양도세 얼마야?"` → tax_calculator (코드 계산 + 근거 내역)
6. `"저신용자 무직도 가능하다는 대출 문자 왔는데 진짜야? 수수료 먼저 입금하라고 해"` → fraud_check 대출 빙자
7. `"비트코인 리딩방에서 USDT 입금하면 월 30% 보장한대, 괜찮아?"` → fraud_check 가상자산 리딩방 + 고수익 보장
8. `"[국세청] 환급금 124만원 확정. 오늘까지 링크에서 계좌 입력"` → fraud_check 환급 사칭 + 126 안내

> 각 답변 하단에 어떤 도구가 동작했는지 status 이벤트가 스트리밍으로 표시됨 — "근거 파이프라인이 보인다"는 포인트를 발표에서 짚을 것.

### 심화 시나리오 D — "계산은 코드로, 근거는 그래프로, 한계는 고지로" (~90초)

맞춤형 + 결정론 + 근거 추적이 한 흐름에서 이어지는 시연. §3 코어 시나리오 종료 후 선택적으로.

| Step | 행동 | 확인 포인트 |
|---|---|---|
| D-1 | 챗에 입력: `"5억에 산 아파트 8년 됐는데 팔면 양도세 얼마야?"` | tax_calculator가 단계별 내역(양도차익→장기보유특별공제→기본공제→누진세율→지방교육세)과 법령 근거(소득세법 §97·§100의5·§55)를 함께 표시 — 같은 질문을 다시 물으면 **같은 숫자**(결정론 증거) |
| D-2 | 이어서 입력: `"사실 조정대상지역이야"` | 비과세 한도가 12억→9억으로 반영돼 재계산 — **대화 맥락이 계산 입력으로 들어가는 맞춤형** |
| D-3 | 이어서 입력: `"그 계산 근거 법령 원문 보여줘"` | doc_rag/graph_rag가 국세청 해설서 발췌 + 출처 칩 표시, `/graph`에서 해당 조항 엔티티 추적 가능 |
| D-4 | 답변 말미 면책 문구 확인 | "실제 세액과 다를 수 있는 단순 계산기" 고지 — 한계를 스스로 밝히는 정직성 |

> 발표 포인트: "숫자는 LLM이 아니라 코드가 계산하고, 근거는 클릭으로 추적되며, 한계는 AI 스스로 고지합니다" — 신뢰 아키텍처 3겹이 한 화면에.

### 심화 시나리오 E — "같은 문자, 다른 행동 요령(맞춤형 증명)" (~90초)

> **결정론으로 구현됨**: 페르소나별 행동요령은 LLM 재량이 아니라 `fraud_check`가 프로필 연령대를
> 코드로 분류(`classify_persona`)해 고정 블록(`_PERSONA_ACTION`)을 붙인다 → 같은 문자면 **항상 같은
> 맞춤 요령**. 답변에 `적용 프로필: 고령층 맞춤/청년 맞춤/일반`이 명시돼 맞춤형이 눈에 보인다.

| Step | 행동 | 확인 포인트 |
|---|---|---|
| E-1 | `/me`에 시니어 조건 입력 → 위 #4 문자 입력 | `적용 프로필: 고령층 맞춤` — 큰 단계·짧은 문장(**저장된 번호로 확인**→112→1332→가족 알림). 문자에 찍힌 번호로 되걸라는 안내는 발신번호 변작·악성앱 가로채기 때문에 코드·프롬프트 양쪽에서 금지돼 있다 |
| E-2 | 청년 조건으로 바꿔 같은 문자 재입력 | `적용 프로필: 청년 맞춤` — "은행/경찰은 이런 식으로 돈을 요구하지 않는다" 원칙+악성앱 함정+셀프 대처 |
| E-3 | 발표 포인트 | "탐지는 경쟁작도 합니다. 우리는 누가 받았는지에 따라 '무엇을 해야 하는지'가 **코드로** 달라집니다 — 결정론이라 매번 같습니다" |

| 1 | AI 환각을 구체적으로 어떻게 막나? | ① grounding 지시 상시 삽입 ② doc_rag passage 출처 강제 ③ GraphRAG 원문 추적 ④ 도구 화이트리스트 ⑤ temperature 0.3 낮춤 — "프롬프트 한 겹이 아니라 구조로 방어" |

| 5 | 투자자문 규제는? | 자문업 아닌 정보 제공 프레이밍, 면책 고지, 개인화는 '집단 벤치마크' 방식 |
| 6 | 왜 올인원인가? | 정보 파편화가 문제이므로 해결책도 통합이어야 함. 허브(대화)+스포크(전문화 화면) 구조 |

| 8 | LLM 비용은? | intent→fan-out→synthesize 단일 패스 설계로 LLM 호출은 질문당 최대 2회(intent 라우터 300토큰 상한 + 작문 1회)뿐 — 검색·계산·사기판정은 전부 코드/DB라 호출 없음. NVIDIA NIM 무료 티어(RPM 40) 안에서 동작하며 보조 키 로테이션으로 심사 기간 여유 확보. `[ ]` 회당 평균 토큰 실측치 |
