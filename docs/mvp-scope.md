# MVP 스코프 — 2026 금융 AI Challenge

2026-08-20 확정. 배경: 앱에 기능이 너무 많고 흔한 조합(주식 기술분석 챗봇)이라 상 받기 어렵다는 문제의식에서
시작한 스코프 재설계.

## 대회

- **2026 금융 AI Challenge** (금융보안원 주최, 상금 3,500만원, 923팀 경쟁)
- 예선(9/7 10:00 제출: 기획서 + 기능명세서 + 배포 URL) 심사 = **100% "주제 적합성"** 내부 심사 → 상위 11팀만 발표 진출
- 대회 예시주제 중 **"청년층 자산형성·포용적 금융서비스"**가 기존 자산과 가장 잘 맞음. 주식 기술분석/백테스트는
  예시주제 어디에도 안 걸림 — alpha 미입증(`validate_calibration_moat.py`, n=133)까지 겹쳐 이중으로 약한 축.

## 타겟 & 문제

- **타겟**: 무주택 사회초년생
- **문제(금융현안)**: 청약 조건·세금·자금마련 정보가 여러 곳에 흩어져 있어 자기 상황에 뭐가 적용되는지
  이해 못 하고 기회를 놓침 — 정보 비대칭.
- **포지셔닝**: "판단"이 아니라 "근거와 함께 정리·설명". 자문 아님 명시. 세무사법·자본시장법 무자격 자문
  형사리스크 회피 + alpha 없음 문제를 동시에 해소하는 방향(8/13 결정 연장선).

## 핵심 여정 (헤드라인)

1. **청약 상담** — 챗봇이 GraphRAG 근거(세법·청약 조문, 근거 서브그래프)로 "이 조건에서 어떤 청약 유형·
   특별공급 자격이 적용되는지" 정리. RAG 인입 파이프라인(`pipelines/embedding/document_parser.py` →
   `reingest.py`)은 이미 있는 걸 그대로 사용.
2. **목표자금 확인** — 해당 주택형의 목표금액 기준. **분양가 vs 청약 예치금, 사용자가 선택**.
   ~~일반 분양 APT엔 분양가 필드가 없다~~ — **틀린 서술이었음(2026-08-20 정정)**. `api_client.py:261`이
   매핑하는 `lttot_top_amount`(공급금액 상한, 만원 단위)는 임대뿐 아니라 **일반 APT 공고에도 실제로 채워짐**
   (라이브 확인: 123,300만원 등). 그래서 `DetailModal.tsx`가 주택형별 `lttot_top_amount` 최대값을 원 단위로
   환산해 `/simulator?target=…`으로 넘긴다. 청약 예치금 표(지역×전용면적, 「주택공급에 관한 규칙」 제28조 —
   하드코딩)는 공고를 안 고르고 들어온 사용자를 위한 **대안 축**이고 유일한 축이 아님. 값이 비어 있는 공고는
   `/simulator`로 target 없이 보내고 직접 입력을 쓰게 한다.
3. **자금마련 타임라인 시뮬레이터** (**독립 페이지 `/simulator`**, 네비 core) —
   현재 자산 + 월 저축액 + 상품(적금/예금, 정책상품 포함) 입력 → 목표 도달 시점 시각화, "이 상품 쓰면
   O개월 당겨짐" 비교. 상품 후보 서제스천은 이미 있는 `product_research_node`(네이버 검색 기반 예금·
   적금·연금저축·국채ETF 라이브 조회)를 재사용 — 새 데이터 파이프라인 불필요.

**데모 시나리오(초안)**: 28세 무주택 사회초년생, 서울 거주, 현재 자산 2,000만원, 월 저축여력 60만원.
서울 전용 59㎡ 특별공급 관심 → 예치금 기준 목표(이미 충족) 확인 → 실질 목표는 계약금·중도금 대비
자금 마련 → 시뮬레이터가 "지금 적금 vs 청년도약계좌" 비교해서 몇 개월 당겨지는지 시각화.
